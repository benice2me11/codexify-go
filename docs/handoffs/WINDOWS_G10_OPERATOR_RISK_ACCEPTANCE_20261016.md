# Windows G10 — операторская приёмка Go-only с исключениями

**Дата решения:** 16 октября 2026 года.

**Статус:** `G10_OPERATOR_ACCEPTED_WITH_DEVIATIONS` — текущая работающая Go-only сборка принята по эксплуатационному решению пользователя.

**Формальный результат строгого теста:** `G10_STRICT_HOLD` (не переписан на PASS).
**Сфера:** только уже работающий Windows `CodexifyGo`, а не новая сборка Project Groups, rollout Setup v4, релиз 0.9.0 или полная приёмка G11.

## Решение

Пользователь согласился не задерживать приёмку текущего Go-only коннектора из-за повторного набора непрерывных 24 часов, поскольку предшествующая эксплуатация Go уже была достаточно продолжительной. Новые сбои будут расследоваться **по факту возникновения**, с использованием сохранённой телеметрии и обычных критериев безопасности.

Это **явное принятие риска неполноты непрерывного soak**, а не заявление, что все предусмотренные G10 тесты объективно пройдены. Оригинальные G10-логи, события `HOLD` и исходные критерии приёмки сохраняются без изменения.

## Отклонения, принятые решением

- Нет 24 часов **непрерывной** записи наблюдений одной и той же текущей сборки: окно пересечено перезагрузкой, есть пробелы и два `HOLD`.
- Метрики G10 «50 намеренных действий», две рабочие сессии, три 15-минутных idle-окна, p95 по 20 hosted reads и полное сравнение CPU/памяти не были по отдельности закрыты новым итоговым сертификатом. Их нельзя считать автоматически пройденными.
- История других Go-сборок подтверждает реальную эксплуатацию, но не доказывает непрерывную стабильность точного текущего SHA256.

**Операторская трактовка:** перечисленные неполные измерения **приняты как остаточный риск**, поэтому не блокируют продолжение работы уже запущенного Go-коннектора. Факты о пропусках не скрываются.

## Неприкосновенные критерии безопасности

Решение **не** отменяет проверку единственного владельца tunnel/SCM, защиту binding и файловых границ, контроль отсутствия Rust, запрет автоматического Rust fallback, изоляцию артефактов, явную идентификацию кандидата и SHA256, а также требования безопасного восстановления предыдущего Go.

При подтверждённых дублирующихся владельцах, потере локального управления, неправильной маршрутизации между репозиториями, утечке секретов или самоподдерживающемся MCP burst требуется немедленное расследование и остановка опасного действия. При обычных VPN/tunnel 403/429/503 — диагностика и управляемое восстановление дочернего процесса; такой сетевой эпизод сам по себе **не** повод для отката на Rust.

Каждый будущий инцидент фиксировать с UTC-временем, SHA256 работающего Go, состоянием SCM и Task Scheduler, числом владельцев, симптомами, корреляцией с Windows boot/VPN и классификацией причины. Применять исправление адресно, с регрессионным тестом; не откатывать весь коннектор без доказанного локального дефекта.

## Отдельные операции, на которые это решение не распространяется

- **Go→Go обновление до Project Groups:** новый бинарник имеет SHA256 `F5AF36CEA944688CB8BF6145F8047722CA23F991E077DA1D7897D74B2D3A0DB2`, его эксплуатационная приёмка и отдельное операторское переключение ещё не выполнены.
- **Строгий автоматизированный G10 readiness:** продолжает возвращать `HOLD` для неполного окна; это честные измерения, а не статус оператора. Любое исключение для нового canary требует явного самостоятельного решения с сохранением жёстких safety-gates. Не менять `Assess-ProjectGroupsCanaryReadiness.ps1` так, чтобы он ложно сообщал `PASS`.
- **Project Groups feature flag:** в production остаётся `false`; Setup v4 в реальном ChatGPT не принят.
- **G11 и релиз 0.9.0:** не считаются автоматически закрытыми. Релизный HOLD действует до отдельного решения.
- **Вакансии/автоматизация:** `Vacancy Hourly Watch` не включался, отклики не отправлялись.
