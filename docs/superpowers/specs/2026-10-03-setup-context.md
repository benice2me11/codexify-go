# Setup UI conversation context
The user authorized autonomous diagnosis, a legitimate context fix, a new candidate, live A/B UI verification, and then G06. The metadata probe proves model calls carry openai/session while actual UI calls have none of the five identity fields or a stateful transport identity.
Use an opaque, server-issued setup context obtained from the originating model tool result. Resolve it to the original server-observed conversation metadata. Never infer an anonymous identity from a desktop UUID, accept an arbitrary thread ID, edit bindings, or change the installed host.
Contexts are 32 random bytes encoded as URL-safe base64, expire after 30 minutes, remain in memory only, and are bounded to 1024 entries. Issue them only for a persistent conversation identity and reuse one per identity until expiry. Existing transport-based clients continue to work without them.
The context authorizes only list_projects, setup_status, set_project_root, and setup_ui_switch_project on the already authenticated MCP channel. Any explicit conflicting conversation identity, unknown/expired token, malformed token or use on another tool must fail before dispatch. Tokens must never appear in model-visible output, logs, or diagnostics.
Deliver the token in result _meta under io.github.devnoname120/codexify/setup-context. The setup widget reads direct metadata and the canonical call_tool_result/mcp_tool_result envelopes from toolResponseMetadata and sends uiContext in its tool arguments. Do not initiate tools from global-change notifications. Keep the error-display fix.
Model calls remain unchanged; context applies only within one request and cannot leak to later calls. The server restart invalidates contexts but preserves existing conversation bindings. Tests must prove isolation, failure before mutation, expiry/restart behavior, and no host-event request loops.
Live deployment must use an isolated frozen candidate, verified complete managed tunnel runtime, zero-owner handoff, and the already authorized independent rollback guard. G05 requires actual A UI switch/selection plus A/B checks. Do not inherit gate PASS for a new candidate. An actual Windows reboot remains a separate user-confirmed action.
